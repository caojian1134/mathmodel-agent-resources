# 收录与检查方法

## 收录边界

目录面向数学建模竞赛和开放式数学建模工作，收录以下类型：

1. 能组织审题、建模、计算、验证或交付的 Agent；
2. 以 `SKILL.md` 或相似协议描述数学建模流程的技能包；
3. 与运筹优化、数据分析 Agent 或求解器反馈有关的支撑项目；
4. 可直接用于训练和复现的算法、模板及赛题资源。

本目录不以论文为主体，也不收录只有营销介绍、无法找到公开入口或明显重复的条目。

## 2026-09-06 快照检查

对可下载项目进行了以下只读检查：

- 确认原始仓库 URL；
- 记录本地快照 commit；
- 统计仓库中的 `SKILL.md`；
- 检查根目录是否存在 `LICENSE`、`LICENSE.txt` 或 `COPYING`；
- 对新增 Skill 做网络命令、子进程、删除命令、动态执行和 API Key 关键词扫描；
- 不运行第三方脚本，不安装依赖，不配置密钥。

“根目录未观察到许可证”只是本次快照的文件检查结果，不是法律意见。仓库可能随后增加许可证，也可能在子目录或外部页面说明授权。

## 不采用的排名方法

- 不按 Star 数直接排序；
- 不把文件或 Skill 数量等同于质量；
- 不依据作者自述的“工业级”“稳定版”等标签直接认证；
- 不因代码能运行就推断模型结论正确；
- 不因项目与论文关联就推断它适合正式比赛。

## 推荐评价维度

| 维度 | 核心问题 |
|---|---|
| 任务覆盖 | 能否处理题目、数据、模型、代码、验证和交付？ |
| 人机边界 | 是否保留人工决策与停止点？ |
| 可追溯性 | 数字、图表和结论能否追溯到代码与数据？ |
| 可复现性 | 是否记录依赖、随机种子、输入和输出？ |
| 安全性 | 是否会访问网络、执行命令、覆盖或删除文件？ |
| 合规性 | 是否适配目标比赛当届规则和 AI 披露要求？ |
| 许可证 | 是否允许当前使用、修改和分发方式？ |

## 更新建议

更新条目时，优先提交可核验事实：原始链接、commit、许可证路径、最小运行命令、测试结果和明确失败条件。动态数据应附查询日期。
